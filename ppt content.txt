PROJECTMATCH — PRESENTATION CONTENT

Use this document as the complete source brief for creating a polished presentation about ProjectMatch.

PRESENTATION GOAL

Create a premium, modern startup-style presentation explaining ProjectMatch as a student project-team discovery and collaboration platform. The presentation should feel product-led, visual, and credible—not like a generic college CRUD application.

Recommended tone: confident, thoughtful, clear, human, product-focused.
Recommended visual direction: dark midnight navy, black, crisp white, and blue accents. Use clean product screenshots or UI mockups, thin borders, generous whitespace, subtle grid details, and restrained motion. Avoid excessive gradients, neon gaming aesthetics, generic dashboards, and dense paragraphs.


SLIDE 1 — TITLE

Title: ProjectMatch
Subtitle: Find the people who make ideas move.

Supporting line:
ProjectMatch helps students discover projects, meet compatible teammates, and build stronger teams through transparent matching.

Visual direction:
Use a hero view of the ProjectMatch workspace with a midnight blue interface, match scores, project cards, and a subtle blue grid or connection motif.

Speaker note:
ProjectMatch is designed around a simple belief: good student projects are not limited by ideas; they are often limited by finding the right people to build them with.


SLIDE 2 — THE PROBLEM

Title: Finding a project team is still strangely hard.

Key points:

- Students often discover projects through scattered chats, informal groups, or last-minute invitations.
- Skill compatibility is usually judged by guesswork.
- Students may have useful skills but not know which projects need them.
- Project owners struggle to balance technical skills, roles, interests, and availability.
- Existing solutions often feel like directories, portfolios, or college administration systems.

Core insight:
The challenge is not only discovering people. It is understanding whether they will work well together.


SLIDE 3 — THE OPPORTUNITY

Title: Student collaboration needs a better matching layer.

Message:
ProjectMatch connects the supply of student skills with the demand of real project ideas.

It helps answer:

- Who is a strong fit for this project?
- Why are they a strong fit?
- Which skills are missing from the current team?
- Which teammate would improve the team balance most?
- Can students connect without needing to know each other first?


SLIDE 4 — THE SOLUTION

Title: ProjectMatch turns discovery into a guided collaboration flow.

Product loop:

1. Create a student profile.
2. Discover projects and people.
3. See transparent compatibility scores.
4. Understand why the match works.
5. Build a balanced project team.
6. Invite teammates and manage collaboration locally.

Key differentiator:
ProjectMatch does not show only a percentage. It explains the match.


SLIDE 5 — PRODUCT EXPERIENCE

Title: One workspace for the entire team-building journey.

Main areas:

- Overview dashboard
- Student discovery
- Project discovery
- Project detail pages
- Student profile detail pages
- Team builder workspace
- My Teams collaboration hub
- Profile onboarding and editing
- Settings and theme preferences
- Login experience

Visual suggestion:
Show a connected product map with Overview → Discover → Project → Match → Team Builder → Invite.


SLIDE 6 — STUDENT ONBOARDING

Title: Onboarding feels like setup, not paperwork.

The onboarding flow collects:

- Name and role
- Avatar/profile identity
- Short bio
- Skills
- Skill proficiency
- Interests
- Availability
- Previous project experience

UX decisions:

- The form is split into logical steps.
- Progress is visible at every stage.
- Each step has one clear question.
- Validation prevents incomplete profiles.
- Profile data is saved locally in the browser.

Product benefit:
Students can quickly create enough context for meaningful matching without filling out a long intimidating form.


SLIDE 7 — STUDENT PROFILES

Title: Profiles show more than a name and a list of skills.

Each profile includes:

- Avatar
- Name and role
- Short bio

- Interests
- Availability
- Previous project experience
- Compatibility with relevant projects
- Shared interests with other students

React — 90%
JavaScript — 84%

Profiles should make it easy to understand both what a student can do and what kind of work they care about.

Discovery capabilities:

SLIDE 11 — THE MATCHING ENGINE

Title: Transparent matching without pretending to be AI.

ProjectMatch uses deterministic JavaScript scoring. No machine learning or external AI API is required.

Scoring model:

- Skill compatibility — 50%
- Interest compatibility — 20%
- Role compatibility — 10%
- Availability — 10%
- Previous experience — 10%

Scores are normalized to a range of 0–100.

Example:

94% MATCH

Positive reasons:

- Strong React proficiency
- Relevant Python experience
- Shared climate interest
- Availability lines up

Warning reasons:

- Limited UI/UX experience
- Different interest areas


SLIDE 12 — EXPLAINABILITY

Title: A score is useful only when people understand it.

The compatibility panel breaks the score into:

- Skills
- Interests
- Role
- Availability
- Experience

Each category has:

- A percentage
- A weighted contribution
- A short human-readable reason

Product benefit:
Students can make informed decisions instead of blindly trusting an unexplained ranking.

- Required roles and skills

- Filled and missing states
- Team gaps

CENTER — Current team:

- Selected members
- Roles
- Key skills
- Individual match percentages
- Overall team compatibility
- Remove member actions
- Persistent team state

RIGHT — Recommended teammates:

- Ranked candidates
- Project match
- Missing-skill coverage
- Role coverage
- Team diversity considerations
- View profile
- Invite member

SLIDE 16 — INVITATIONS AND LOCAL STATE

Architecture principles:

- Centralized storage abstraction
